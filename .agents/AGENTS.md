# Workspace Rules

1. **Verify Builds**: After writing or modifying code, ALWAYS run `npx tsc --noEmit` in the background to ensure everything compiles correctly without TypeScript or ESLint errors. Do not consider a step fully complete until the build passes.
2. **Design Quality**: Make sure every page design is properly aligned, fully responsive, and visually appealing ("wow" factor). Use shadcn/ui components effectively, ensure proper spacing (margins/padding), and use Tailwind CSS for all styling.
3. **Theme & Color Consistency**: Always use CSS variables (e.g., `bg-primary`, `text-primary`, `bg-background`, `text-foreground`) for UI branding and layouts instead of hardcoded Tailwind colors like `blue-500` or `cyan-500`. This ensures the entire website theme can be instantly swapped for different clients by simply modifying the CSS variables Iin `globals.css`.
4. **Mobile View Strict Separation**: When redesigning or modifying the mobile view UI (to emulate a native Android app), DO NOT alter the desktop view. Maintain strict separation between mobile and desktop designs. Only adjust shared components if a feature update explicitly requires changes in both contexts.
5. **Bright Text Colors**: Always use fully bright colors for active or primary text elements. If text is meant to be white, use full white (`#ffffff` or `text-white`). If text is meant to be tinted (e.g., blue-ish), use a fully bright version of that color. The only exception is unselected or intentionally muted text (e.g., unselected nav bar items or secondary labels), which can remain dimmed.
6. **Skeleton Loader Accuracy**: If any design or layout is changed in either mobile or desktop views, ALWAYS update the corresponding skeleton loaders to exactly match the new design layout (including heights, padding, rounded corners, grid columns, and overall structure). Skeletons must mirror the final loaded component as accurately as possible.
